# Documentation maintenance

## Purpose
Keep project guidance accurate, concise, discoverable and free of competing sources of truth.

## Approach
1. Identify the audience and purpose of each document.
2. Inspect current source and relevant existing documentation.
3. Assign one canonical owner to each topic.
4. Separate current implementation, current user-approved direction, proposals and historical context.
5. Remove obsolete instructions and duplicated explanations rather than relocating them by default.
6. Keep AI entry instructions short; put technical detail in focused references and skills.
7. Use consistent skill frontmatter and a simple structure: purpose, when to use, approach, project context and deliverable.
8. Check links, file paths, commands, terminology and contradictory statements.
9. State the evidence scope and update dates for snapshots.

## Rademan context
AGENTS.md is the concise AI entry point. AI/DEVELOPMENT-GUIDE.md is the central engineering guide. Skills are optional, focused and adaptable. The user's latest explicit direction supersedes historical instructions and AI defaults.

## Deliverable
A clear documentation change set, ownership map, validation results and remaining gaps. Do not preserve obsolete material solely for archival completeness.
