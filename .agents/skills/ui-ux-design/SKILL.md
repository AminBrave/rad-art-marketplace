# UI and UX design

## Purpose

Make user goals clear through purposeful hierarchy, content, layout and interaction.

## Use when

Use when a screen, journey, navigation model or visual/interaction system needs design or review. Use a lightweight pass for isolated corrections.

## Workflow

1. Understand audience, task, content, context, constraints and success criteria.
2. Inspect the current screen, route, tokens, shared components and user journey.
3. Choose a visual direction grounded in the product and brief rather than a generic template.
4. Define hierarchy, navigation, content, layout and interactions before decoration.
5. Design relevant loading, empty, error, success, disabled and permission states.
6. Implement semantic elements and reusable components where they fit.
7. Critique against the brief; inspect screenshots/browser behavior when available and refine.

## Rademan context

Rademan is an art discovery and artist–audience platform. Respect [design guidance](../../../AI/DESIGN-SYSTEM.md), [product context](../../../AI/PROJECT.md) and [localization](../../../AI/LOCALIZATION.md). Persian RTL, English LTR and mixed-direction content matter.

## Quality bar

Prioritize legibility, keyboard/focus, contrast, responsive behavior and reduced motion. Use tokens without treating them as immutable. Avoid generic card grids, decorative labels and gratuitous animation.

## Deliverable

A concise design rationale, journey/screen specification or implementation with key states, accessibility/localization considerations and review evidence.
