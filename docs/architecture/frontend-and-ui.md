# Frontend Architecture and UI

Entry: `resources/js/app.jsx`. Router: `app/AppRouter.jsx`. Auth: `AuthContext.jsx`. Route guards/layouts: `RoutingPages.jsx`, `Layouts.jsx`. Feature screens are lazy-loaded at route boundaries.

## UI foundation: shadcn/ui is the core

shadcn/ui is the single source of truth for reusable interface primitives. It is source-owned UI code, not a runtime component package. Components in `resources/js/components/ui/` follow shadcn APIs, variants, accessibility patterns, and semantic Tailwind tokens. Use the shadcn CLI/registry to add or update primitives; do not introduce a second component framework or a parallel set of generic controls.

- `components.json` configures shadcn CLI: New York style, JavaScript, RTL, CSS variables, existing `@` aliases.
- `resources/js/components/ui/` contains the canonical shadcn primitives. Feature-specific compositions may live alongside them only when they express Rademan domain concepts (for example, ArtworkCard and ArtistCard).
- `resources/js/lib/utils.js` owns the shared `cn()` helper.
- `resources/css/rademan-theme.css` is the brand-theme configuration. It supplies shadcn semantic tokens and Rademan brand extensions. Change brand appearance here, not in individual primitive files.
- `resources/css/app.css` owns Tailwind directives and application/layout styles; it must not become a second token or generic component system.
- Tailwind 3.4 and the current Vite/Laravel build remain in place during UI standardization. Do not combine a Tailwind major-version upgrade with this migration.

## Theme contract

The component-facing API is shadcn semantic variables: `--background`, `--foreground`, `--card`, `--primary`, `--secondary`, `--muted`, `--accent`, `--destructive`, `--border`, `--input`, `--ring`, and `--radius`. Rademan's ivory, charcoal, terracotta, sand, olive, Vazirmatn/Inter typography, spacing, radii, and shadows are defined in `rademan-theme.css`. Legacy color aliases remain temporarily so existing feature screens can migrate without a flag day. New components must use shadcn semantic tokens.

Persian-first and RTL are product requirements. `components.json` enables RTL-aware CLI output. Keep `dir="rtl"` at the document/application root and use logical utilities such as `ms-*`, `me-*`, `ps-*`, `pe-*`, `border-s`, and `border-e`. Verify menus, dialogs, pagination, calendars, and directional icons in RTL and LTR.

## Component catalog

The shadcn/ui registry is the approved component catalog. Add components from it as needed; do not hand-roll equivalents or add another UI kit. The approved catalog includes Accordion, Alert, Alert Dialog, Aspect Ratio, Avatar, Badge, Breadcrumb, Button, Calendar, Card, Carousel, Chart, Checkbox, Collapsible, Command, Context Menu, Dialog, Drawer, Dropdown Menu, Form, Hover Card, Input, Input OTP, Label, Menubar, Navigation Menu, Pagination, Popover, Progress, Radio Group, Resizable, Scroll Area, Select, Separator, Sheet, Sidebar, Skeleton, Slider, Sonner, Switch, Table, Tabs, Textarea, Toggle, Toggle Group, and Tooltip. This is the project-wide standard; generate only components actually needed by active routes.

Existing Radix-backed interaction components and Lucide React remain valid implementation dependencies. Do not remove a Radix dependency until imports and generated components are audited and the package lock is regenerated by the package manager. Do not add a competing UI system.

## Route areas

Public home/catalogue/artwork/artist/collections/info/auth; artist dashboard/profile/artworks/messages; buyer dashboard/messages; admin dashboard/users/artwork moderation/reports/editorial. Inquiry screens remain in source but their routes, navigation and public entry points are hidden while the registry flag is false.

## Application behavior

Feature availability is read through `isFeatureEnabled()` from the Laravel-injected `window.__RAD_FEATURES__` registry. Gate route declarations, navigation and public feature entry points with the same flag; backend feature middleware remains authoritative and returns 404 for disabled endpoints. Auth context owns the current user; transient form and presentation state stays local to screens. Axios uses same-origin Laravel session/CSRF conventions. TanStack Query owns cacheable public discovery data in the homepage, artwork catalogue/detail, artist directory/profile and collection pages, and passes AbortSignal to Axios requests; account identity changes clear the shared cache so user-scoped results cannot survive a logout/account-switch boundary; queries that may return private records also include viewer identity in their query key. Client role checks never protect data.

Support narrow mobile widths without horizontal overflow. Include loading, empty, error, success and unavailable-media states. Use semantic elements, labels, keyboard focus, accessible names and meaningful image alt text. Keep shareable pagination/filter state in URL when useful. Prevent stale async updates and duplicate requests; follow AbortController patterns.

## Verification

Run `npm ci`, `npm run test:frontend`, `npm run lint`, `npm run build`, and the repository's Laravel/browser verification commands in CI. Test public, buyer, artist, and admin routes; direct links and role redirects; keyboard interaction; dialogs/menus; Persian RTL and LTR; responsive widths; and Inquiry-disabled behavior while direct messaging remains available.
